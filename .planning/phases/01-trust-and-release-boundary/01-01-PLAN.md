<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → repo | Third-party packages cross into the build via create-expo-app/npm install |
| local env files → git history | Developer-local secrets must never cross into version control |
| Expo app config → native build | app.json privacy manifests flow into generated native projects |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-SC | Tampering | npm installs (create-expo-app, expo, expo-template-default, vitest, RNTL, zod) | mitigate | Blocking human-verify legitimacy checkpoint (Task 1) + SDK 57 stable line only + versions selected by create-expo-app/expo install, never canary |
| T-01-01 | Information Disclosure | .env files → git history | mitigate | .gitignore `.env*` entry; .env.example documents non-secret-only policy |
| T-01-02 | Tampering | Scaffold provenance | mitigate | Official create-expo-app with default template only; no community templates; package publisher verified in Task 1 |
</threat_model>
