## Phase Goal (user story)

**As a** prospective LemAstra user, **I want to** understand the supported product, its providers, and its privacy posture, **so that** I know what leaves my device before any remote feature is enabled.

This plan delivers the PRIV-07 vertical slice: registry data → validated schema → rendered disclosure screen → app entry routing.

<objective>
Build the provider registry as versioned, schema-validated data and render it as the app's Privacy & Data screen, making it the first thing a user sees. One data source feeds the UI now and the store-disclosure drafts in plan 01-06.

Purpose: PRIV-07 requires a reviewable disclosure surface before any remote feature exists; registry-driven content prevents drift between what users see and what governance documents claim.
Output: provider-registry.json, zod schema + tests, app/privacy.tsx screen + component test, index routing.
</objective>
