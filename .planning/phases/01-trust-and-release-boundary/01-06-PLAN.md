## Phase Goal (user story)

**As a** prospective LemAstra user, **I want to** understand the supported product, its providers, and its privacy posture, **so that** I know what leaves my device before any remote feature is enabled.

Store disclosures are where privacy claims become binding — this plan drafts them from the single registry and locks consistency with tests (GATE-05 part 2).

<objective>
Derive Apple privacy-label and Google Play Data-safety drafts from the provider registry and inventory, and add structural/consistency tests that hard-fail when governance docs or disclosures drift.

Purpose: GATE-05 requires store disclosures that match the approved inventory; both stores use fixed taxonomies that do not transfer between each other, so each draft answers within its own taxonomy from the shared source.
Output: disclosure drafts under docs/governance/disclosures/ + two structural test files.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| registry data → store disclosures | Store answers are binding legal claims; they must derive from approved data |
| taxonomy misuse → app review rejection | Both stores review against fixed taxonomies; invented categories fail review |

| T-01-13 | Repudiation (legal) | Cross-store taxonomy contamination (Apple terms in Play answers) | mitigate | Separate artifacts per store; each task restricted to its own official taxonomy; Play CSV header from Google's template |
| T-01-14 | Tampering | Governance docs silently deleted/restructured later | mitigate | governance-docs structural tests fail on missing files/sections |
