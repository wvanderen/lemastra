## Phase Goal (user story — slice 3 of 7)

**As a** LemAstra user, **I want to** see my calculated chart as a wheel and tap any factor in it, **so that** I can read that factor's exact calculated facts next to the chart instead of a bare list.

*(Derived from ROADMAP Phase 4 Goal + Success Criteria 1.)*

**Planner param-design decision (discretion: "Exact explore-route naming and revision-vs-latest param semantics"):** `/chart/explore?id={chartId}` with optional `&revision={revisionId}` (latest by default; the revision chain stays read-only per Phase-3 D-07). D-01 forbids envelope params, and the repository is web-unavailable (03-03 D-03), so: on **/chart/saved** the card pushes by chartId; on **/chart/result** the card pushes directly when the chart is saved (save.data.chartId / the revise-flow chartId param), and when unsaved it first opens the existing SavePrompt (PRIV-01 explicit-save-only) then pushes with the newly returned chartId. On **web** the card does not mount (D-04: no graphical wheel on web) and the explore route renders the WebUnsupported capability card — a web /chart/explore visit is genuinely data-less (id-param lookup + web-unavailable repository), so the card is the honest deep-link posture, not a scope reduction. D-04's full web evidence experience (dual views, lists, fact panels, facts — no canvas) ships on the **web branch of /chart/result**, the one web screen that holds the in-memory envelope: **04-07 Task 2** mounts ModeToggle + EvidenceLists + FactPanel there with selection via pressable rows (D-10), once ModeToggle exists (04-06). Per user decision resolving the plan-check blocker — D-04 delivers as written, in this phase.
