## Spacing Scale

Declared from the existing `Spacing` tokens in `src/constants/theme.ts` (do not introduce raw values):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`Spacing.one`) | Inline gaps, glyph spacing inside placement rows, chip padding |
| sm | 8px (`Spacing.two`) | Compact gaps between related controls, card internal sub-gaps |
| md | 16px (`Spacing.three`) | Default screen padding, card padding, gaps between cards |
| lg | 24px (`Spacing.four`) | Section separation within a screen |
| xl | 32px (`Spacing.five`) | Screen-level grouping (header block → content block) |
| 3xl | 64px (`Spacing.six`) | Major screen breaks (reserved; rarely needed) |

Exceptions:
- **Touch targets:** every interactive control has a hit area ≥ 44pt (iOS) / 48dp (Android) — confidence segments, tricky-time options, house-system rows, CTAs, candidate cards. Visual height may be smaller with `hitSlop`.
- **Existing `Spacing.half` (2px):** retained for micro-gaps between degree glyphs (e.g. `0°26′`) only.
- **Phase-1 legacy:** `privacy.tsx` hand-rolled values (6/12/13/15/17) are legacy — new Phase-2 screens use the tokens above and the typography scale below. Card *radius* 8 and 1px hairline border carry forward from `privacy.tsx` as the card treatment.

## Typography

Uses existing `ThemedText` styles; no new text styles. Exactly 4 sizes, exactly 2 weights in this phase's screens:

| Role | Size | Weight | Line Height | Maps to |
|------|------|--------|-------------|---------|
| Body | 16px | 500 (regular) | 24 (1.5) | `ThemedText type="default"` |
| Label | 14px | 500 (regular) | 20 (1.43) | `type="small"` — field labels, helper text, list secondary text, assumptions line |
| Heading | 24px | 600 (semibold) | 30 (1.25) | screen titles on `/birth` and `/birth/confirm`; section headings on result |
| Display | 32px | 600 (semibold) | 40 (1.25) | `type="subtitle"` — result-screen title only |

- Semibold (600) is reserved for headings, selected-state labels, and emphasis inside body copy. Do **not** use weight 700 in Phase-2 screens (existing `smallBold` stays unused).
- **Data exception:** machine values — coordinates, UTC offsets, version/hash strings, IANA zone ids — render in the existing `code` style (12px `Fonts.mono`, weight 500) for legibility and visual separation from prose. This is the only sub-14px text.
- Body line-height 1.5 and heading line-height 1.25 are mandatory. `allowFontScaling` stays on (default) — layouts must wrap, not clip, at large text sizes.

## Color

60/30/10 split, driven by `useTheme()` so light/dark both hold. Two new semantic tokens are added to `Colors` in `src/constants/theme.ts` (single source of truth — no hard-coded hexes in components):

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) | `background` #FFFFFF | `background` #000000 | Screen background |
| Secondary (30%) | `backgroundElement` #F0F0F3 | `backgroundElement` #212225 | Cards: place candidates, resolved-place card, tricky-time options, placement rows, unavailable-factors cards, assumptions card, disclosure cards |
| Accent (10%) | **new** `accent` #2266CC | **new** `accent` #7AB0FF | See reserved list below |
| Selected surface | `backgroundSelected` #E0E1E6 | `backgroundSelected` #E2E3E8→#2E3135 | Fill of the selected segment/option/radio row |
| Secondary text | `textSecondary` #60646C | `textSecondary` #B0B4BA | Helper text, list secondary lines, assumptions values, provenance labels |
| Error (semantic) | **new** `error` #B3261E | **new** `error` #F2B8B5 | Recoverable-error banners only |

Contrast basis (assumption A-UI-2): #2266CC on #FFFFFF ≈ 5.5:1 and white on #2266CC ≈ 5.5:1 (AA); #7AB0FF on #000000 ≈ 9.5:1; error tokens ≥ 6.5:1 on their backgrounds.

**Accent reserved for — the complete list:**
1. Primary CTA fill ("Review birth details", "Calculate chart", "Got it — Calculate chart") with white (light mode) / near-black (dark mode) 16px/600 label.
2. Selected-state indicators on choice controls: the radio marker dot + 2px option-card border on the confidence control, tricky-time picker, and house-system rows.
3. Text links to governance surfaces: "Read full privacy details" → `/privacy`, and the link-styled "Enter coordinates manually" toggle.

Accent is **not** used for: body text, headings, icons/decoration, borders of unselected cards, or validation status. `linkPrimary` in `themed-text.tsx` migrates from hard-coded `#3c87f7` to the `accent` token (mechanical change; keeps one source of truth).

**Error color reserved for** recoverable-error banners (CALC-04) and inline field-validation messages. There are **no destructive actions in Phase 2** (chart deletion arrives in Phase 3). Tricky-time and drift notices are *attention, not error*: they use the secondary card + 600-weight heading, never the error color.

**Validation status** on the result screen renders as neutral `textSecondary` text with a text label ("Validated") — no green/success hue is introduced this phase.

## Copy Deck (authoritative strings)

The progressive-disclosure audience constraint governs every string: beginner-first phrasing, technical precision on demand. `{…}` marks server-supplied values (from the resolve/calculate payloads). Do not paraphase these strings ad hoc in components; collect them in one module (e.g. `src/components/birth/copy.ts`, `src/components/chart/copy.ts`) so tests assert exact copy.

### Home (`/`)
- Heading: "LemAstra"
- Sub-line (Label): "Accurate charts. Transparent evidence."
- CTA: "Calculate your first chart"
- Link: "See what we send — privacy & data"

### Birth form (`/birth`) — title: "Birth details"
- Date label: "Birth date" · placeholder "YYYY-MM-DD" · error "Enter a valid date (YYYY-MM-DD)."
- Time label: "Birth time" · placeholder "HH:MM (24-hour)" · error "Enter a valid time, like 09:30 or 1430."
- Place label: "Birthplace" · placeholder "City or town (e.g. Lisbon)"
- Place search loading: "Searching…"
- Place zero results: heading "No match found for “{query}”." · hint "Try a nearby city or a larger place name." · action "Enter coordinates manually"
- Place unavailable: heading "Place search is unavailable right now." · hint "Check your connection and try again." · action "Enter coordinates manually"
- Selected candidate: coords line (Data mono) "{lat}°, {lon}°" · precision note when `location_type` is `APPROXIMATE` or `partial_match`: "Approximate match — verify before calculating." · action "Change"
- Manual fallback toggle: "Enter coordinates manually" ↔ "Search by name instead"
- Manual fields: "Place name" placeholder "For reference on your chart"; "Latitude" error "Enter a number between −90 and 90."; "Longitude" error "Enter a number between −180 and 180."; "Time zone" (searchable picker from `/api/v1/meta/zones`) error "Choose a time zone."
- Confidence control heading: "How well do you know your birth time?" · options + helper text (Label):
  - **Timed** (default): "From a record — birth certificate, hospital paperwork, or a reliably remembered exact time."
  - **Approximate**: "Roughly known, like “around 7 in the morning”. Houses and angles are calculated but flagged provisional."
  - **Rectified**: "Estimated by an astrologer working backward from life events."
  - **Unknown**: "No time known. You'll get only what doesn't need a time — planets in signs. No houses or rising sign, and nothing is guessed."
- Unknown side effect: time field is disabled and cleared; its helper becomes "Not needed when the time is unknown."
- Advanced control header: "Assumptions & advanced" (collapsed; expands in place)
  - House system label: "House system" · default **Whole Sign** · options exactly: Whole Sign, Placidus, Regiomontanus, Koch, Equal, Campanus, Porphyrius, Morinus, Alcabitius, Topocentric
  - House-system helper: "Whole Sign is the default and works everywhere, including extreme latitudes. Quadrant systems like Placidus can fail near the poles."
- Form CTA: "Review birth details"

### Confirm screen (`/birth/confirm`) — title: "Confirm birth details"
- Resolved place card (field labels Label/600, values Body; coords and zone in Data mono):
  - "Birthplace" → `{label}`
  - "Coordinates" → `{lat}°, {lon}°`
  - "Time zone" → `{iana_zone}`
  - "UTC offset at birth" → `{offset_label} ({timeZoneName})` — the locally resolved historical offset, per D-06/D-07
  - Drift note (only when `drift: true`): "Note: Google's current-rules offset differs from the historical record for this date. We used the historical one."
- Birth summary line (Label, textSecondary): "{date} · {time} · {confidence}"
- Zone source note (Label, textSecondary): "Time zone resolved via Google (server-side)" or "Time zone entered manually"

### Tricky-time picker (on confirm screen, only when `classification ≠ "normal"`)
- Ambiguous — heading: "This time happened twice" · body: "On {date}, clocks fell back in {iana_zone}, so {time} occurred twice. Which one is your birth time?" · options (labels from server payload):
  - "First {time} — {offset_label}" / helper "Before the clocks changed"
  - "Second {time} — {offset_label}" / helper "After the clocks changed"
- Nonexistent — heading: "This time didn't exist" · body: "On {date}, clocks sprang forward in {iana_zone}, so {time} never happened." · single option "Use {shifted_time} instead ({offset_label}) — the closest real time after what you entered."
- Picker footnote (both cases): "We never pick for you — ambiguous times change the chart."
- A required choice blocks Calculate until made (CTA disabled + helper "Choose a time above to continue").

### One-time disclosure (D-04) — first-run intercept on "Calculate chart"
- Heading: "Before your first calculation"
- Intro (Body): "Here's exactly what leaves your device, where it goes, and for how long — from our privacy registry:"
- Content: **registry-driven** — render the `lemastra-calculation` and `google-geocoding-timezone` entries from `src/data/provider-registry.json` using the Phase-1 card pattern (data-category chips, "When it sends", "Retention", "Purpose"). The component must contain **no provider content of its own** (test-enforced Phase-1 invariant).
- Registry status note: both providers show "Active" only after the governed `planned → active` flip; the notice renders either way from the same data.
- Primary CTA: "Got it — Calculate chart" (sets `@lemastra:disclosure.calculation.v1` and proceeds; never re-shown)
- Link: "Read full privacy details" → `/privacy`

### Calculating state
- CTA disabled + label "Calculating chart…" + `ActivityIndicator`. No partial result renders; failure lands in the error banner.

### Result screen (`/chart/result`) — title (Display): "Your natal chart"
- Identity line (Label, textSecondary): "{date} · {time} · {label} · {confidence}" (Unknown mode omits `{time}`)
- Placement list heading: "Placements" · column layout per row: Body (Body/600) — "{sign} {degree}" — "House {n}" — Motion — Dignity
  - Degree format: `D°MM′` from `degree`, minutes rounded (e.g. "Gemini 0°26′"); motion displayed capitalized: "Direct" / "Retrograde" / "Stationary"
  - Dignity renders only where present: "Domicile", "Exaltation", etc.; no empty column or placeholder dash
  - Row accessible label: "{body} in {sign}, {degree spoken as “X degrees Y minutes”}, {house phrase}, {motion} motion" (+ ", {dignities}" when present)
- Assumptions card (D-12 compact): label "Assumptions" (Label/600) + value (Label, textSecondary): "{house_system} houses · {zodiac_mode} zodiac · {ephemeris_mode} ephemeris · {orb_policy}" · action "Adjust & recalculate" (returns to `/birth` with the advanced control open)
- Expandable "Calculation details" (collapsed by default): Data-mono key–value rows — Skill revision, Swiss Ephemeris version, Timezone database, Schema, Input revision, Place resolution (zone source + provider), Calculator command
- Validation status (Label, textSecondary): "Validated — passed chart schema {schema_version}"
- Unavailable factors (Unknown mode only, D-10): section heading "Not available without a birth time" · one card per `unavailable_factors` entry: "{Factor} — {reason}" (e.g. "Houses — requires a birth time"; "Rising sign & Midheaven — requires a birth time"; "Sect — requires sunrise/sunset timing"; "Lots — the Lot of Fortune needs the Ascendant")
- Provisional factors: card "Provisional" · "{factor} — {reason}" (e.g. Moon: "the Moon moves about 13° per day; its degree may shift without a known time"). Approximate mode: assumptions card gains "Angles and houses are provisional for approximate times."

### Error banners (CALC-04) — one pattern, per-class copy
Pattern: card with 1px error border, error-colored heading (Label/600), body in Body/text color, hint in Label/textSecondary, and a recovery **action** where one exists. Heading prefix is always "Couldn't…"-style — meaning never rides on color alone.

| `error_code` | Heading | Body + recovery |
|---|---|---|
| `PLACE_ZERO_RESULTS` | "No match found for “{query}”." | "Try a nearby city or a larger place name." + action "Enter coordinates manually" |
| `PLACE_PROVIDER_UNAVAILABLE` / `TIMEZONE_PROVIDER_UNAVAILABLE` | "Place search is unavailable right now." | "Check your connection and try again." + action "Enter coordinates manually" |
| `TIMEZONE_NO_RESULTS` | "We couldn't resolve a time zone for these coordinates." | "Pick the time zone manually below." |
| `PLACE_INVALID_QUERY` / `TIMEZONE_INVALID_ZONE` | "That search couldn't be processed." | "Shorten the query and try again." |
| `CALC_INVALID_INPUT` | "Birth details couldn't be processed." | Server field message (already user-facing copy, verified) + "Fix the highlighted field and try again." |
| `CALC_UNSUITABLE_HOUSE_SYSTEM` | "{house_system} houses can't be calculated for this location." | "Switch to Whole Sign or Equal houses under Assumptions, then calculate again." + action "Open Assumptions" |
| `CALC_TIMEOUT` | "Calculation timed out." | "Try again — this is usually temporary." + action "Try again" |
| `CALC_ENGINE_ERROR` | "Calculation failed." | "Try again. If it keeps failing, your details are fine — this is on our side." + action "Try again" |
| `CALC_VALIDATION_FAILED` | "The service returned a chart that failed validation." | "Nothing is wrong with your input. Please try again; if it persists, wait for a fix." |
| network / API unreachable | "Can't reach the calculation service." | "Check your connection and try again." |

No destructive confirmations exist in this phase.

## Screen & Flow Contracts

Route structure follows research §7 (expo-router file routes):

```
src/app/index.tsx          → landing: title, sub-line, CTA → /birth, privacy link
src/app/birth.tsx          → Birth entry form
src/app/birth/confirm.tsx  → Place & time confirmation + tricky-time + disclosure intercept + Calculate
src/app/chart/result.tsx   → Structured placement list result (no wheel — D-13)
```

### `/birth` — Birth entry form (BIRTH-01, BIRTH-04)
Layout (single `ScrollView`, `SafeAreaView` insets, max content width per `MaxContentWidth`):
1. Heading "Birth details" (24/600)
2. Date field → Time field (disabled+cleared when confidence = Unknown)
3. "Birthplace" — type-ahead search (see Interaction Contract) with persistent "Enter coordinates manually" toggle; manual branch swaps in Place name / Latitude / Longitude / Time-zone picker
4. Confidence control — inline four-state segmented control ("How well do you know your birth time?"), radio semantics, `Timed` default
5. "Assumptions & advanced" collapsed disclosure → house-system radio list (Whole Sign default)
6. Primary CTA "Review birth details"
7. Link "See what we send — privacy & data" → `/privacy`

Field errors render inline under each field (Label, error color). The form validates client-side (zod) before navigation; the server revalidates (CALC_INVALID_INPUT path maps back to fields).

### `/birth` → `/birth/confirm` transition (BIRTH-02)
Tapping "Review birth details" triggers the resolve-time call (`POST /api/v1/places/resolve-time`) and navigates only on success; the draft travels as router params (JSON-stringified, research A3). Resolve failures render on `/birth` per the error table — the manual fallback is the always-available escape hatch.

### `/birth/confirm` — Confirmation (BIRTH-02, BIRTH-03, D-04, D-06)
Layout order: heading → resolved-place card → birth summary line → tricky-time picker (when classification ≠ normal; blocks Calculate until a choice is made) → confidence summary → CTA "Calculate chart" → back link "Edit birth details" (returns to `/birth` with values intact).
First run only: tapping "Calculate chart" opens the disclosure intercept; its "Got it — Calculate chart" CTA acknowledges and continues. Subsequent runs calculate directly.
Calculation is a user-initiated mutation (`useMutation`, no auto-retry on non-network errors); in-flight state disables the CTA.

### `/chart/result` — Result (D-10, D-12, D-13, CALC-02/03)
Layout order: Display title → identity line → "Placements" list → assumptions card → "Calculation details" (expandable) → validation status → unavailable-factors section (Unknown mode) → provisional-factors cards (Unknown/Approximate).
Guard: arriving without a calculated payload redirects to `/birth`. Every fact is a list row — **no wheel, no preview graphic** (D-13).

## Interaction Contract

**Place type-ahead (D-05):** debounced ≥ 300 ms, fires at ≥ 3 characters, max 5 candidates rendered as cards (secondary surface, radius 8, hairline border, ≥ 48px hit area). Selecting a candidate fills the resolved card state with coords + precision note. Zero-results and unavailable states inline under the field, each offering the manual action. Keyboard dismisses on selection. Manual entry is reachable from both states and from the field's persistent toggle link.

**Confidence control (D-09):** inline segmented control, four options, radio group semantics; selected segment = `backgroundSelected` fill + accent marker + 600 label (never color alone). Selecting `Unknown` disables and clears the time field with the helper swap defined in the copy deck. No modal, no separate screen.

**Tricky-time picker (D-08):** renders only when the server classification is `ambiguous` or `nonexistent`. Radio-selectable option cards using the server-provided option labels (verified payload format: first/second pass with offsets, or the shifted instant with explanation). Calculate is disabled until a selection exists. The chosen `time_resolution` mode is what the calculate request carries — the UI never re-derives offsets itself.

**House-system selector (D-11):** collapsed under "Assumptions & advanced"; radio list of the 10 verified names; Whole Sign default and pre-selected; selection changes calculation inputs (recalculate to see effects). Quadrant-failure recovery: the `CALC_UNSUITABLE_HOUSE_SYSTEM` banner's "Open Assumptions" action deep-links back to this control.

**Progressive disclosure (audience constraint):** the assumptions line is always visible (compact), full provenance is one expansion away, and helper text accompanies every concept a beginner hasn't met (confidence states, DST, house systems). Technical users get exact mono values (coords, offsets, versions) without leaving the screen.

**Navigation/state:** linear flow only; back never loses entered data (params-carried draft). The result screen's "Adjust & recalculate" returns to `/birth` with the advanced control open. No persistence this phase (Phase 3).

**Loading/failure:** every async surface (search, resolve, calculate) has explicit loading, empty, and error treatments per the copy deck — no spinners-only states, no silent retries of calculations.

## Accessibility Contract

- Targets ≥ 44pt/48dp; hitSlop where visual size is smaller.
- Confidence control: `accessibilityRole="radiogroup"` / `radio` with `accessibilityState={{ checked }}`; house-system list and tricky-time options identical.
- Placement rows expose one-sentence labels (copy deck format); list containers use `role="list"`/`listitem` per the Phase-1 `privacy.tsx` pattern.
- No meaning by color alone: selected = fill + marker + weight; error = border + heading text; provisional/unavailable = labeled cards.
- Dynamic type: default font scaling on; rows and cards wrap (tested at 1.3× in component tests).
- Screen-reader order matches visual order: heading → identity → placements → assumptions → details → status.
- The disclosure intercept, tricky-time picker, and error banners are announced (`accessibilityLiveRegion="polite"` on banner text where platform-supported).

## Trust-Boundary Display Rules (project constraint)

- Every value on the result screen is a **calculated fact** until labeled otherwise; no interpretation appears in Phase 2.
- Unavailable ≠ missing: absent factors render as explicit labeled cards with reasons — never blank rows, placeholders, or invented values (no noon chart — D-10).
- Provisional ≠ uncertain prose: approximate-time and Moon caveats render as labeled cards keyed off server `provisional_factors`/confidence data.
- Assumptions and provenance are always reachable (compact line → expandable details); the disclosure surface stays registry-driven so UI can never drift from governance (Phase-1 invariant).
