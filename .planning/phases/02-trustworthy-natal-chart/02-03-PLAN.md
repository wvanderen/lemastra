## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → calculate endpoint | Untrusted request body (user-entered birth data) crosses into the API |
| API → calculator subprocess | Translated input crosses into the AGPL tool |
| calculator stdout → API response | Tool output is re-validated before it becomes the response envelope |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-09 | Tampering | POST /api/v1/charts/calculate request | mitigate | pydantic models at the edge: lat/lon bounds, date/time patterns, closed enums for house_system/confidence/mode; calculator revalidates (exit 2); vendored schema gate on output |
| T-02-10 | Tampering | response envelope | mitigate | jsonschema Draft202012Validator against vendored chart_input_schema.json before returning (CALC_VALIDATION_FAILED otherwise) |
| T-02-11 | Information Disclosure | error responses | mitigate | engine tracebacks logged server-side only; response carries code/message/hint only (verified against test_errors caplog assertions) |
| T-02-12 | DoS | calculate endpoint | mitigate | inherited per-request subprocess + timeout from 02-01; request models bound field sizes |
| T-02-13 | Repudiation | provenance | accept | input_revision hash + version chain make every chart self-describing for later audit (full non-repudiation is a Phase 3+ persistence concern) |
</threat_model>
