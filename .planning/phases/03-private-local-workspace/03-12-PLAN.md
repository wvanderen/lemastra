<objective>
Close the final open Phase-03 UAT gap: a populated api/.env with GOOGLE_API_KEY must produce a working local API when started exactly per the README — place search returns results — and a missing key must be visible without a 503 round-trip.

Purpose: UAT gap 3 (03-UAT.md, severity minor, status failed) proved api/.env is loaded by NO code path: settings.py reads raw os.environ (deliberately, no pydantic-settings — that decision stands), `uv run` does not load .env, and uvicorn's `--env-file` would crash with ModuleNotFoundError because python-dotenv is not in the locked dependency set. The documented README start command therefore silently drops the key and place search answers 503 PLACE_PROVIDER_UNAVAILABLE; it only ever "worked" when the key happened to be exported in that shell. This is the developer-experience defect that blocks the local calculate→save flow (WORK-01/WORK-02) on a fresh machine.

Chosen fix — candidate (c) from the gap's missing list: a minimal built-in .env bridge inside settings.py, plus the optional visibility item (startup warning + health flag). Rationale over the alternatives: (a) python-dotenv + `--env-file` adds a locked dependency whose only consumer is a CLI flag — forgetting the flag reproduces the exact silent 503 this gap is about; (b) documenting `set -a && source .env && set +a` keeps a forgettable pre-step AND executes the file as shell script (arbitrary code in a config file); (c) wires loading at the single site that reads configuration, so the existing README command works unmodified, with zero dependency churn under the exact-pin/uv.lock discipline, and a restrictive parser that never executes anything — strictly safer than the workaround it replaces.

Output: settings.py .env bridge (loader + precedence contract), main.py keyless visibility (startup warning + health places_search_available flag), parser and health tests, README/.env.example documentation truth.
</objective>

  <files>api/lemastra_api/settings.py, api/tests/test_dotenv.py</files>
  <action>
    Gap reason (03-UAT.md gap 3 root cause): api/.env is never loaded by any code path — settings.py reads plain os.environ with nothing wiring the documented .env file to it. Missing item 1, candidate (c).

    1. In api/lemastra_api/settings.py add `import logging` and a module-level logger. Add a module constant `_DOTENV_PATH = Path(__file__).resolve().parents[1] / ".env"` (parents[1] is the api/ directory — the same location-independent resolution pattern as the existing `_REPO_ROOT`, because uvicorn may be launched from api/ or the repo root and the file must be found either way).

    2. Add `_load_dotenv(path: Path) -> None`: if the path is not a file, return silently (missing .env is the documented keyless dev posture — no warning). Otherwise read it as UTF-8 and process line by line with a 1-based line number: strip each line; skip blanks; skip lines starting with "#"; drop one optional leading `export ` prefix; if no "=" is present, log a warning and skip; split on the FIRST "=" into key and value; strip the key (empty key after strip → warning + skip); strip the value, then remove ONE pair of matching surrounding single or double quotes when value length >= 2 and first and last characters match; apply with `os.environ.setdefault(key, value)` so variables already present in the real environment — including present-but-empty ones — are never overridden. Deliberate omissions, documented in the docstring: no variable interpolation, no escape sequences, no multiline values, no command execution. Malformed-line warnings carry the file name and line number ONLY — never key or value text (a mangled line could contain a pasted secret).

    3. Call `_load_dotenv(_DOTENV_PATH)` as the first statement of load_settings(); the existing os.environ reads stay byte-identical. Update the module docstring: still plain os.environ reads, no pydantic-settings (decision unchanged) — now preceded by a minimal .env bridge where real environment variables take precedence over api/.env; document the supported grammar.

    4. Create api/tests/test_dotenv.py. Env hygiene law for this file: the loader may introduce keys into os.environ that monkeypatch would not otherwise clean up, so every key a test lets the loader define must first go through `monkeypatch.setenv(KEY, "sentinel")` followed by `monkeypatch.delenv(KEY)` — monkeypatch then restores the exact prior state (including prior absence) at teardown even after setdefault injects a value; use file-unique key names (DOTENV_TEST_*) for grammar cases so no other test file could ever read them. Cover: full-line comment and blank line skipped; `export ` prefix parsed; value containing "=" preserved (split on first); single- and double-quoted values stripped of one matching pair; mismatched quotes left verbatim; empty value allowed (KEY=); malformed lines (no "=", empty key) skipped with a caplog-captured warning whose text contains the line number and NOT the line content; real-env precedence (pre-set key not overridden; present-but-empty string also not overridden); missing file is a silent no-op. End-to-end: monkeypatch settings._DOTENV_PATH to a tmp_path .env containing GOOGLE_API_KEY and LEMASTRA_ALLOW_ORIGINS lines (both keys pre-cleaned via the hygiene idiom) and assert load_settings() returns google_api_key and allow_origins from the file.
  </action>
