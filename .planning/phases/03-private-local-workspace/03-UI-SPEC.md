# Phase 3 — UI Design Contract

> Visual and interaction contract for the private local workspace: save, browse, reopen, revise, rename, export, and delete charts — plus the /privacy "Your data" controls. Generated by gsd-ui-researcher (autonomous mode), verified by gsd-ui-checker.
>
> **Scope:** `/` (workspace list), `/chart/result` (Save CTA), `/chart/saved`, `/chart/revision`, `/birth` (prefilled revise path), `/privacy` ("Your data" section).
> **Out of scope:** wheel and evidence views (Phase 4), transits (Phase 5), interpretation (Phase 6+), PDF export (Phase 9), any account surface (never in v1).
>
> **Baseline:** this contract inherits the approved 02-UI-SPEC design language unchanged — same tokens, same typography scale, same card treatment, same copy-deck discipline. Phase 3 adds surfaces; it does not restyle existing ones.

## Spacing Scale

Inherited from the existing `Spacing` tokens in `src/constants/theme.ts` (do not introduce raw values):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`Spacing.one`) | Inline gaps, chip internal padding, glyph spacing |
| sm | 8px (`Spacing.two`) | Compact gaps between related controls, card internal sub-gaps, badge row gaps |
| md | 16px (`Spacing.three`) | Default screen padding, card padding, gaps between cards, modal padding |
| lg | 24px (`Spacing.four`) | Section separation (hero → list, list → footer), modal outer spacing |
| xl | 32px (`Spacing.five`) | Screen-level grouping (header block → content block on home) |
| 3xl | 64px (`Spacing.six`) | Major screen breaks (retained; rarely needed) |

Exceptions:
- **Touch targets:** every interactive control has a hit area ≥ 44pt (iOS) / 48dp (Android) — chart list rows, history rows, action rows, dialog buttons, CTA. Visual height may be smaller with `hitSlop`.
- **Existing `Spacing.half` (2px):** retained for micro-gaps only (degree glyphs).
- **Chart list row height:** rows are content-sized (label + identity line + badges), minimum 48dp, `backgroundElement` fill, radius 8, hairline border — the OptionCard card treatment, non-selectable variant.
- **Phase-1 legacy:** `privacy.tsx` hand-rolled values are legacy; the new "Your data" section uses the tokens above and the typography scale below.

## Typography

Inherited exactly from 02-UI-SPEC — no new text styles. Exactly 4 sizes, exactly 2 weights in this phase's screens:

| Role | Size | Weight | Line Height | Maps to |
|------|------|--------|-------------|---------|
| Body | 16px | 500 (regular) | 24 (1.5) | `ThemedText type="default"` — dialog body copy, list primary labels, action labels |
| Label | 14px | 500 (regular) | 20 (1.43) | `type="small"` — identity lines, chips/badges, helpers, dialog secondary text |
| Heading | 24px | 600 (semibold) | 30 (1.25) | screen titles and the "Saved charts" / "History" section headings |
| Display | 32px | 600 (semibold) | 40 (1.25) | `type="subtitle"` — saved-chart title (the chart label) and result title only |

- **Modal/dialog headings render at Body size with weight 600** (16/600). The 24px Heading is reserved for screen-level titles; dialog hierarchy stays subordinate to screen hierarchy. 600 is otherwise reserved for headings, selected-state labels, emphasis, and dialog/CTA labels — no weight 700 in Phase-3 screens.
- **Data exception:** machine values — revision ids, `input_revision` digests, IANA zones, file names — render in the existing `code` style (12px `Fonts.mono`, weight 500). Only sub-14px text in the app.
- Body line-height 1.5 and heading line-height 1.25 mandatory. `allowFontScaling` stays on; chart labels of any length wrap, never truncate to a fixed-height clip (up to the 60-char validation bound below).

## Color

60/30/10 split driven by `useTheme()` so light/dark both hold. **No new tokens this phase.** The existing `error` token's reserved-use list extends to destructive actions (the only genuinely new visual semantic in Phase 3):

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) | `background` #FFFFFF | `background` #000000 | Screen background, modal card surface |
| Secondary (30%) | `backgroundElement` #F0F0F3 | `backgroundElement` #212225 | Chart list rows, history rows, badges/chips, "Your data" cards, save prompt surface, saved-state CTA fill |
| Accent (10%) | `accent` #2266CC | `accent` #7AB0FF | See reserved list below |
| Selected surface | `backgroundSelected` #E0E1E6 | `backgroundSelected` #2E3135 | "Saved ✓" disabled CTA fill; retained selected-control role from Phase 2 |
| Secondary text | `textSecondary` #60646C | `textSecondary` #B0B4BA | Identity lines, list secondary text, chip text, helpers, section intro copy |
| Error / destructive | `error` #B3261E | `error` #F2B8B5 | See destructive list below |

Contrast basis (from 02-UI-SPEC A-UI-2, unchanged): accent ≈ 5.5:1 (light) / 9.5:1 (dark); error tokens ≥ 6.5:1 on their backgrounds; destructive confirm fill carries a white (light) / near-black (dark) label at 16/600 — same pairing as the accent CTA.

**Accent reserved for — the complete Phase-3 list:**
1. Primary CTA fills: home "Calculate your first chart" / "Calculate a chart", result-screen "Save chart", save-prompt confirm — with white (light) / near-black (dark) 16/600 label.
2. Selected-state indicators on choice controls (no new choice controls this phase; role retained).
3. Text links to governance surfaces: "See what we send — privacy & data", "Read full privacy details".

Accent is **not** used for: body text, headings, icons/decoration, badges, unselected borders, the "Saved ✓" state (neutral), export actions, or destructive controls.

**Error color reserved for — the complete Phase-3 list:**
1. Recoverable-error banners and inline field validation (Phase-2 role, unchanged).
2. **Destructive triggers:** the "Delete chart" action row on the saved-chart detail and the "Delete all data" action in "Your data" — Label or Body size, weight 600, error-colored text on the standard card.
3. **Destructive confirm buttons** inside both delete dialogs — error fill, white/near-black 16/600 label, mirroring the accent CTA geometry.

Destructive meaning never rides on color alone: every destructive control carries the word "Delete" in its label, and every destructive dialog restates what is removed in plain text. Cancel is always the default-toned button.

**No success/green hue is introduced.** "Saved ✓" and delete-all completion are neutral (`backgroundSelected` fill / `textSecondary` text with explicit wording).

## Interaction Contract

**Save (D-10):** explicit only — nothing persists without the Save CTA (PRIV-01). CTA → modal label prompt (input prefilled with the smart default, autofocus) → validate (1–60 trimmed) → pending (buttons disabled) → "Saved ✓". Double-tap protection: CTA disabled while pending. Fresh-flow saves create a new chart; revise-flow saves append under the originating chart; dedupe key is (chart, input_revision).

**List & reopen (D-11, D-02):** rows navigate to `/chart/saved?id=`. Reopen reads by id and re-parses the stored envelope (parse-then-trust) — zero network calls (test-enforced). Ordering: `updated_at` desc — rename and revision-append both refresh position.

**Rename (D-12):** inline title swap (no modal); Save name commits `label` + `updated_at` only; Cancel restores. List refreshes via query invalidation.

**History (D-07):** prior revisions read-only; the latest is marked and non-navigational. "What changed" is a derived human phrase (vocabulary above), never a raw diff.

**Deletion (D-14/D-15):** both destructive paths are modal-confirm-gated, naming scope and permanence; confirm is the only error-filled element; cancel is default and always available. Single delete removes chart + all revisions transactionally; delete-all wipes personal tables only. No swipe-to-delete, no long-press shortcuts — deletion is never accidental.

**Export (D-13):** writes `lemastra-chart-<slug(label)>-<revision-id>.json` (pretty-printed JSON of envelope + identity + label + ids) to cache via the OO File API, then the native share sheet (`application/json`), gated on `Sharing.isAvailableAsync()`. Filename never renders raw user input beyond the sanitized slug; the share sheet is the user's delivery choice. Export pending state on the trigger; failure lands in the error banner.

**Web degradation (D-03):** repository mount short-circuits; home shows the capability card; /privacy export/delete disabled with the app helper. No storage code path on web.

**Telemetry (D-16):** no analytics surface exists; no UI copy promises tracking; log call sites exclude chart payloads (test-enforced — invisible in UI, listed here so the auditor can verify no telemetry UI leaked in).

**Navigation/state:** back from saved detail returns to home with list state intact (TanStack Query cache); no flow loses entered data. All mutations invalidate `['charts']` + detail keys (03-RESEARCH Pitfall 10).

## Accessibility Contract

- Targets ≥ 44pt/48dp everywhere, `hitSlop` where visual size is smaller.
- Chart list and History list: `role="list"`/`listitem` with one-sentence accessible labels (copy deck); rows are single-tap navigation, no nested ambiguous targets — chips are decorative text inside the row label.
- Dialogs: RN `Modal` with `accessibilityViewIsModal`, focus trapped by the modal surface, heading announced first; destructive confirm buttons labeled with their full action ("Delete chart", "Delete everything").
- No meaning by color alone: destructive = the word "Delete" + error color; "Saved ✓" = text + neutral fill; badges are text chips (secondary fill), never color-only dots; confidence marker spells the confidence name.
- Dynamic type on: labels wrap to 60 chars; rows and dialogs grow, never clip; tested at 1.3× in component tests (Phase-2 precedent).
- Screen-reader order matches visual order on every screen; the save prompt announces validation errors (`accessibilityLiveRegion="polite"` on field error, Phase-2 banner precedent).
- Export/delete outcomes announced politely (completion text is real rendered text, not toast-only).

## Trust-Boundary Display Rules (project constraint)

- A saved chart renders **only** stored, re-parsed evidence (D-02) — reopening never recalculates; every fact on `/chart/saved` and `/chart/revision` is a calculated fact from the stored envelope, labeled exactly as in Phase 2.
- Revisions are visibly immutable: History marks the Latest, earlier versions are read-only with an explicit marker, and no surface implies an old analysis changed basis (WORK-04 trust language: "The current one stays in History.").
- Private-by-default is visible, not just true: save prompt says where data stays ("on this device"), "Your data" states "no account and no server copy" — consistent with the registry's already-published retention strings (governance consistency tests).
- Explicit-save-only: no auto-save, no "we saved this for you" moments; the only persistence trigger is the user's Save action.
- Destructive actions state scope and irreversibility in plain text before confirmation.
